# Explorer notes: provider selection, coding-agent tools, test configuration
- Provider selection (packages/ai/src/models.ts): `Models.stream`/`streamSimple` call `requireChatProvider`, which looks up `model.provider` in a map keyed by provider id (unknown id throws `ModelsError("provider")`). `applyAuth` then resolves auth, and `createProvider` dispatches on `model.api` when a provider has an api map.
- Legacy path (packages/ai/src/compat.ts): `stream()`/`streamSimple()` try `getBuiltinProviderForModel(model)` first, then fall back to `resolveApiProvider(model.api)`, which reads the api registry filled by `registerApiProvider`.
- Tools (packages/coding-agent/src/core/tools/): each tool has its own file (read, bash, powershell, edit, write, grep, find, ls). `index.ts` defines `ToolName`, `allToolNames`, `createTool`/`createToolDefinition`, and the bundles `createCodingTools`, `createReadOnlyTools` and `createAllTools`.
- Tests: root vitest.base.ts aliases workspace packages to their `src`. packages/*/vitest.config.ts set per-package options, e.g. coding-agent merges the base and sets `PI_OFFLINE=1`. packages/tui uses `node --test` (packages/tui/package.json), and ./test.sh runs `npm test` in an isolated HOME with a whitelisted env and no API keys.
